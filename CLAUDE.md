# Notes for Claude

This repo is the live site (GitHub Pages, branch main, root folder). The owner is not technical: do the work, keep explanations plain.

- Live files are in the repo root: `index.html` (generated), `ejs/` (EmulatorJS engine files), `manifest.webmanifest`, `icons/`. `v2/index.html` is only a redirect to the root.
- Source is in `source/`: `src/emu.js`, `src/emu.css`, `src/emu.html`, `src/voice.js`, plus `tracker_body.html` (the Pokédex tracker).
- To rebuild: `cd source && python3 build_standalone.py <build number>`; it writes `index.html` in the root. Bump the build number each update (it shows in the in-app Menu so the owner can tell they have the new version).
- The same source also built a Claude artifact version; code checks `window.claude` and falls back to standalone behaviour when it is absent.
- Never add ROMs or saves to the repo. The ROM is chosen on the phone and stored in the browser's IndexedDB.
- Owner's rules: portrait only, touch only, no save states, no haptics, main buttons only. Voice control is opt-in via the mic button.
- Tested with Playwright and hand-made test ROMs only; never with a real Emerald ROM or a real iPhone, so be honest about what is unverified.
- OLD ENGINE REMOVED (build 30): the previous mGBA-wasm files (`mgba.js`/`mgba.wasm`, beta/) are gone; they are in git history before commit for build 30 if ever needed. The engine is now EmulatorJS (see V2 note below). Menu has Volume, Sound softening (engine filter, default Off) and Sound buffer (default Normal). Zoom was removed (always 100%).

- Map tab (`source/src/hmap.js`): draws the whole Hoenn overworld ON THE PHONE from the user's own ROM (standard Emerald map tables at 0x486578; only the 49 placements are stored in the source). The picture is never stored in the repo (game artwork). Player position is read from the engine snapshot every 2 s only while the Map is on screen: IWRAM 0x5D8C holds a pointer to SaveBlock1 (it moves, so re-read each time); x/y are int16 at +0/+2 (plain map tiles), mapGroup/mapNum at +4/+5. Verified on the user's ROM (Emerald_National_Dex) in the sandbox. An earlier live "stitching" map made the game stutter and was removed: never read the WebGL canvas.

- Computer layout (build 9): CSS media query `(min-width:900px) and (hover:hover) and (pointer:fine)` (never matches phones, so the portrait/touch-only phone layout is untouched). Wide window = big integer-scaled game on the left (`fitScreen` DESK branch), Pokédex stats + live map column on the right, on-screen buttons hidden, key hints shown. Keyboard (arrows, X=A, Z=B, A/S=L/R, Enter=Start, Backspace/Shift=Select, Esc=Menu, M=map, F=full screen) and standard game controllers are in `emu.js` ("keyboard and game controller"). The controller code has NOT been tested with a real controller; the keyboard was tested with Playwright on the user's ROM.
- Speed (build 10): the engine paces itself on the screen refresh, so 120/144/240 Hz monitors ran the game far too fast. `limitSpeed()` in emu.js (runs when the measured refresh is >= 70 Hz) switches the engine to its own timer and tunes it to 59.73 fps (verified with Chromium launched with --disable-frame-rate-limit). The Menu status line shows "game held to N fps" when it is active. The browser tab title also shows the build number.
- Computer layout applies to ANY window with a mouse (hover + fine pointer); narrow windows stack, windows >= 900 px put the Pokédex/map column beside the game. The Menu sheet scrolls when the window is short.
- Keys (build 12, uses physical key codes): arrows/WASD move, Space/X = A, Left Ctrl/Z = B, Q/E = L/R, Enter = Start, Left Shift/Backspace = Select, clicking the game picture = A (mouse only), P = Pokédex finder <-> game, M = map, F = full screen (asks Chromium to lock keys so Ctrl+W is not taken; untested), Esc = Menu. Known catch: Ctrl+W (Ctrl = B plus W = up) closes the browser tab outside full screen. A user-programmable key picker was asked for as a LATER idea (Menu "Controls" row, remember choices in localStorage).

- Audio problem (builds 13-27): the original mGBA-wasm engine (SDL2 ScriptProcessor audio) gave the owner random crackle on Windows/Chrome headphones; EmulatorJS in the same browser was clean, desktop mGBA clean. Pacing work (timer 59.73 fps, dithering, tab-switch handling) stays in emu.js for the old engine. `beta/` = mGBA-wasm 2.x test (still crunchy, can be removed).
- Engine (build 30+, was the V2 test): the app runs on the EmulatorJS engine, files in `ejs/` (GPL-3, see `CREDITS.md`). Adapter is the "engine option B" block in emu.js: ROM via `EJS_gameUrl` blob, save written with `gm.FS.writeFile(gm.getSaveFilePath())` + `loadSaveFiles()`, save changes found by polling `getSaveFile()` every 3 s (crc), input `gm.simulateInput(0, pad, 0/1)` (A=8,B=0,L=10,R=11,Select=2,Start=3,U/D/L/R=4/5/6/7), pause = `toggleMainLoop(0/1)`, volume by setting gain on `EJS_emulator.Module.AL.currentCtx.sources`, memory for the map via `gm.getState()` (16-byte header then mGBA state; IWRAM +0x19000, EWRAM +0x21000; voice.js `snapshot()` uses it when `M.ejs`). EmulatorJS makes its own canvas, which is moved into `.emu-screen` as `#emu-canvas`. A second boot() (restart, new ROM, imported save) reloads the page. EmulatorJS paces itself on audio: 60 fps even with unlimited rAF. Old pacing/soft/rate menu rows are hidden in V2. Tested in Playwright with the owner's ROM (boot, keyboard, save round trip, change detection, map truck state, pause/resume, restart); NOT tested: real PC audio quality, iPhone/Safari.

- Map interiors (build 31): `hmap.js` also draws ANY map (buildings, caves) from the ROM via `roomOf(g,n)` (map header table at 0x486578 + 4*group, then +4*n; warps from the header's events: 8-byte entries x,y,elev,warpId,mapNum,mapGroup). In the full-screen map, blue diamonds mark doors (zoom >= 3): tap one to enter that room, Back returns (stack), and the view follows the player when the game's map changes (amber marker indoors). Tested in Playwright with the owner's ROM (Littleroot house); not every cave/building checked. Rooms are only drawn on the phone, never stored.
- Map (build 35): Sootopolis City (map 0:7) is NOT placed on the overworld; a blue door marker sits inside the dark crater at world (611,192) (extra entry in `worldWarps()`) and opens it as a room sheet. `compositeOf(g,n)` lays out every room reachable without going outdoors (cap 30, shelf-packed 70 tiles wide) on one sheet; doors joining two rooms get matching letters (yellow badges; tap = jump to the other end with a pink ring), exits to outdoors/other sheets are blue diamonds. `blit()` cuts pictures to their edges by hand because iPhone Safari stretches drawImage source rects that stick out. Touchstart is preventDefault'ed on game buttons/screen/map to stop the iOS press-and-hold magnifier.
- Build 35: EmulatorJS's own pop-up ("Click to resume Emulator", shown on iPhone Safari while sound is locked) and menu bar leaked onto the page; hidden by CSS at the end of emu.css. Our Play button resumes the audio context.
- Map pop-out (build 36, desktop only): Menu row "Map in its own window" (`#mn-mappop`, shown only with hover+fine pointer) calls `popOut()` in hmap.js: `window.open` a blank same-origin popup, copies the stylesheets, and MOVES the `#map-view` element into it (listeners and all), so the same code keeps drawing into the popup's canvas; the game is NOT paused (unlike the in-page full-screen map). `$()` in hmap.js falls back to the popup's document; `popIn()` moves the element back (uses `popMV`, since the popup may already be closed). A "Full screen" button / F key in the popup uses the popup's own `requestFullscreen` (it goes full screen on whichever monitor the window is on). Tested in headless Chromium only (popup, game keeps 60 fps, close and X both restore); real multi-monitor and pop-up blockers untested.
